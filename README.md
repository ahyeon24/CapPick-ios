# 캡픽 (CapPick) — iOS

**쌓아 둔 스크린샷을 AI가 정리하고, 기억나는 말로 다시 찾는 아이폰 앱.**

> AI 분석 비용 장당 **1.4원 → 0.85원** · 검색할 때 서버·AI 호출 **0회** · 개인 보관함은 **기기에만** 저장

관련 저장소: [CapPick-server](https://github.com/ahyeon24/CapPick-server)(API 서버) · [CapPick-eval](https://github.com/ahyeon24/CapPick-eval)(AI 비용·품질 측정) · [CapPick-docs](https://github.com/ahyeon24/CapPick-docs)(기획·화면·API 명세)

## 해결하려는 문제

- 캡처는 계속 쌓이는데, 필요할 때 다시 찾기 어렵다.
- 사람은 캡처 속 정확한 문구보다 **주제**를 기억한다. ("그때 본 사주 화면")
- 매번 폴더에 직접 정리하는 건 번거롭다.

## 주요 기능

| 기능 | 어떻게 동작하나 |
|---|---|
| **자동 순차 분석** | 처음 한 번 동의하면 최근 캡처부터 차례로 분석한다. 앱이 꺼져도 다음 실행 때 이어서 하고, 사용량 한도나 서버 장애 때는 캡처를 실패로 만들지 않고 잠시 멈춘다. |
| **폴더 자동 분류** | 폴더 기준에 맞는 **직접적인 근거**가 있을 때만 넣는다. 사용자가 직접 빼거나 넣은 캡처는 AI 재분류가 덮어쓰지 않는다. |
| **말로 검색** | 화면에 그 단어가 없어도 찾는다. 예: "운세"로 검색해 사주 앱 캡처를 찾는다. "지난주"처럼 날짜 표현도 기기에서 해석한다. |
| **캡처 상세** | 사진 앱처럼 옆으로 넘겨 보고, Live Text로 이미지 속 글자를 길게 눌러 선택·복사한다. |
| **로그인 없는 사용** | 계정 대신 앱 설치 단위의 자격으로 서버 요청을 보호한다. |

## 구조

```
 ┌─────────────── iPhone ───────────────┐        ┌──── CapPick-server ────┐       ┌─ Gemini ─┐
 │ 사진 보관함 → 스크린샷 찾기           │        │                        │       │          │
 │ OCR (Apple Vision, 원본 해상도) ──────┼─이미지─▶│ 작업 접수 (같은 요청    │─1회──▶│ 관찰·요약 │
 │                                       │ +글자  │  중복 방지)             │       │          │
 │ 로컬 DB (GRDB) ◀──── 결과 저장 ───────┼────────│ 결과 임시 보관          │◀──────│          │
 │   = 폴더·캡처·검색 색인의 기준 저장소   │        │ 사용량·하루 예산 관리    │       └──────────┘
 │ 검색: 날짜 해석 + 키워드 + e5 임베딩    │        └────────────────────────┘
 │       → RRF로 합쳐 순위 (서버 호출 없음) │
 └───────────────────────────────────────┘
```

- **개인 보관함은 기기에만 있다.** 서버는 AI 호출을 중계하고 결과를 잠시 보관할 뿐, 캡처나 폴더를 영구 저장하지 않는다.
- **검색어는 서버로 가지 않는다.** 검색은 앱에 들어 있는 임베딩 모델(multilingual-e5-small, ONNX)과 키워드 일치를 합쳐 기기에서 처리한다.
- AI 비밀 키는 앱에 넣지 않는다.

## 기술적 결정과 이유

| 결정 | 이유 |
|---|---|
| 검색을 서버에서 **기기로** 옮김 | 검색할 때마다 AI 비용이 들지 않고, 검색어가 서버로 가지 않는다. 캡처 한 장당 AI 호출도 2회 → 1회로 줄었다. |
| 글자 인식(OCR)을 서버 AI에서 **Apple Vision으로** 옮김 | AI 출력 토큰이 약 60% 줄어 장당 분석 비용이 1.4원 → 0.85원이 됐다. 값싼 모델은 글자가 많은 화면에서 OCR을 빠뜨렸다(1,066자 중 190자만 인식). |
| 임베딩 모델: Apple `NLContextualEmbedding` → **ONNX e5-small** | Apple 모델은 시뮬레이터 권한 버그로 검증 자체가 막혔다. Android 출시 가능성도 생겨, 같은 `.onnx` 파일로 두 플랫폼에서 같은 벡터를 내는 쪽을 택했다. |
| 의미 검색 결과는 **1위와 유사도 차 0.03 이내만** 포함 | 유사도 절대값은 검색어마다 분포가 달라 기준선으로 쓸 수 없었다("고양이 사진"처럼 관련 캡처가 없는 검색어의 1위 0.822 ≈ 진짜 정답 0.824). 0.03은 계속 조정할 잠정치. |
| AI가 폴더 기준을 대신 구체화하는 기능은 **만들지 않음** | "제주도 여행"을 AI가 "공항·해변·렌터카"로 풀면 "제주 카페"가 빠질 수 있다. 느슨한 기준 + 쉬운 수동 교정을 택했다. |

## 검색 품질 평가

검색 방식을 정하기 전에 세 가지 전략을 같은 데이터로 비교했다. (`CapPickTests/SearchStrategyEvaluationTests.swift`, 58문서·35질의)

| 질의 유형 | 키워드만 | 임베딩만 | 하이브리드(RRF) |
|---|---|---|---|
| 전체 | 83% | 97% | 97% |
| 짧은 키워드 ("사주") | 90% | 100% | 100% |
| 자연어 ("전에 봤던 사주 결과") | **50%** | **90%** | **90%** |
| 정확한 식별자 (에러 코드, 날짜, 모델명) | 100% | 100% | 100% |

<sub>Top-1 적중률. 직접 만든 소규모 데이터라 실제 앨범 규모(수백~수천 장)에서는 다시 확인이 필요하다.</sub>

중간에 임베딩 정확도가 40%로 떨어지는 결과가 나왔다. 통제 실험으로 원인을 나눠 보니, 테스트 문서의 92%에 "캡처"라는 같은 단어를 넣은 **평가 데이터 설계 문제**였다. 그 수치는 버리고, 실제 분석 결과와 같은 구조로 데이터를 다시 만들어 측정했다.

AI 비용 측정 스크립트와 결과: [CapPick-eval](https://github.com/ahyeon24/CapPick-eval)

## 실제로 겪은 문제

| 증상 | 원인 | 해결 |
|---|---|---|
| "다시 분석하기"를 눌러도 영원히 같은 실패만 돌아옴 | 중복 요청을 막는 키가 캡처 ID와 버전뿐이라, 재시도가 서버 입장에서 같은 요청이 됨 | 키에 재시도 횟수를 넣음. 앱이 꺼졌다 이어서 처리할 때는 키를 그대로 둬 중복 제출을 막음 |
| 사용량 한도에 걸리면 남은 캡처가 줄줄이 "실패"가 됨 | 한도 초과(429)를 일반 실패로 처리 | 캡처를 "대기"로 되돌리고 큐를 잠시 멈춤 (캡처 10장인 시뮬레이터에선 안 보이고, 수천 장인 실기기에서 터질 문제를 미리 막음) |
| "오늘의 운세"를 검색하면 결과가 통째로 사라짐 | 날짜 해석이 "오늘"을 단순 포함으로 찾아 '오늘 찍은 캡처'로 걸러 버림 | 독립된 단어일 때만 날짜로 해석 |
| 상세 화면 이미지가 3배로 확대돼 잘림 | `UIViewRepresentable`의 `UIImageView`가 원본 픽셀 크기를 그대로 씀 | `sizeThatFits`를 구현해 SwiftUI가 제안한 크기를 따르게 함 |

## 현재 상태

- 시뮬레이터와 실기기(무료 Apple ID 서명)에서 로컬 서버와 연결해 동작을 확인했다.
- 앱스토어에는 출시하지 않았다(Apple Developer Program 미가입). 같은 이유로 App Attest는 개발용 우회 모드로만 검증했다.
- 앱이 백그라운드에 있을 때도 분석하는 기능은 작업 중이다. 지금은 앱이 켜져 있을 때 분석하고, 다시 열면 이어서 한다.

## 기술 스택

SwiftUI · Swift Concurrency(actor) · GRDB(SQLite) · ONNX Runtime · swift-transformers · Vision · VisionKit(Live Text) · Photos · Keychain · XcodeGen

## 실행

```bash
xcodegen generate        # project.yml로 Xcode 프로젝트 생성
open CapPick.xcodeproj   # iOS 17 이상, 시뮬레이터 또는 실기기
```

서버([CapPick-server](https://github.com/ahyeon24/CapPick-server))를 로컬에서 `./gradlew bootRun`으로 켜야 분석이 된다.
